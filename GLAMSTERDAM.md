# Glamsterdam integration branch

Not for upstream. This branch is a superset used to test the Glamsterdam RPC surface end to end
before its pieces are landable: it pins a devnet go-ethereum, hardcodes post-Amsterdam
expectations in testgen, and carries one deliberate speccheck failure. Rebase and refresh it as
upstream changes land; do not open it as a PR.

## Refreshing after the devnet geth moves

The `glamsterdam-devnet-7` branch is rewritten often — it moved mid-session once already — and
the fixtures must be generated by the same commit hive runs, or the comparison is meaningless.

```sh
# 1. the geth commit hive will build (or read it back from a run's clientVersions)
git ls-remote https://github.com/ethereum/go-ethereum glamsterdam-devnet-7

# 2. pin the toolchain to it (a version bump, never a `replace`)
cd tools && go get github.com/ethereum/go-ethereum@<sha> && go mod tidy && cd ..
make -C tools build geth

# 3. rebuild hivechain from the hive branch carrying the Glamsterdam generator
go build -C <hive> -o $PWD/tools/hivechain ./cmd/hivechain

# 4. regenerate the chain, then refill every fixture
cd tools && ./mkchain.sh && cd .. && make fill && make test && make lint
```

Expect a whole-tree fixture diff: the block hashes change, so this is one of the few times the
usual "revert unrelated fixture drift" rule does not apply. `make fill` must report zero
failures; `make test` has exactly one known failure, below.

Sanity checks after regenerating:

- `tools/chain/forkenv.json` has `HIVE_AMSTERDAM_TIMESTAMP` (570 at the current parameters)
- `tools/chain/txinfo.json` lists `tx-calltree` and `tx-callrevert`, including a post-fork block
- blocks past the activation block still carry transactions

## Running it

Stage the fixtures into hive's rpc-compat simulator and build the client from the same geth
commit as the pin — never the prebuilt upstream image:

```sh
cp -R tests openrpc.json <hive>/simulators/ethereum/rpc-compat/
# uncomment the two ADD lines in that simulator's Dockerfile (local-only, do not commit)
```

```yaml
# clients-devnet7.yaml — devnet images are listed in ethpandaops/glamsterdam-devnets
# at ansible/inventories/devnet-7/group_vars/all/images.yaml
- client: go-ethereum
  dockerfile: git
  build_args: {github: ethereum/go-ethereum, tag: glamsterdam-devnet-7}
- client: besu
  build_args: {baseimage: ethpandaops/besu, tag: glamsterdam-devnet-7-caa5abf}
```

Always confirm `tests > 0` and that each client actually launched — a client that fails to start
drops its tests silently rather than failing them.

## Known failures

`eth_simulateV1/two-blocks-with-complete-eth-sends` fails speccheck. Post-Amsterdam a
21000-gas transfer to a never-written account runs out of gas, and geth reports that as
`{-32015, "out of gas"}` while `src/schemas/execute.yaml` requires `-32015` messages to match
`^vm execution error.*`. The schema's own description says messages are suggestions and only
codes are enforced, so the pattern looks over-constrained — a standards decision for the
error-code work in #784, not something to patch here.

Only go-ethereum can import this chain today. besu, Nethermind and Erigon disagree with geth on
the EIP-7928 block access list of the activation block, reth fails on a state-root mismatch, and
ethrex on base-fee validation. Tracked in ethereum/execution-specs#3261, which also records that
besu and Erigon pass 1012/1013 and 1013/1013 of the existing BAL vectors — so this is not
something those clients are simply failing to implement.
